# vault-sidecar

A local-first, static-site digital repository built on [Eleventy](https://www.11ty.dev/). Think of it as a personal knowledge vault with a two-pane reading interface, full-text search, drag-and-drop file ingestion, and zero external dependencies at runtime.

> **Origin:** This prototype was originally scaffolded by [Kiro](https://aws.amazon.com/kiro/) (AWS). The `.kiro/specs/` directory contains the original design documents, requirements, and task plans generated by Kiro. The project was subsequently renamed from `moleskintag` to `vault-sidecar` and extended with additional features and design refinements.

## Features

| Feature | Description |
|---------|-------------|
| **Two-Pane Reader** | Sidebar index on the left, content stage on the right. Progressive-enhancement SPA feel without a framework. |
| **Client-Side Search** | Fuse.js powered full-text search across titles and tags. |
| **Tag Filtering** | Click tags in the sidebar to filter the index. Multiple tags use AND logic. |
| **Drag-and-Drop Upload** | Drop `.md`, `.html`, or `.txt` files onto the sidebar to ingest them into `src/content/`. |
| **Conflict Handling** | Uploads prompt for overwrite when a file already exists. |
| **HTML Isolation** | HTML content renders inside a Shadow DOM so its styles never bleed into the app chrome. |
| **Type Filtering** | Filter by file type (`.md`, `.html`, `.txt`). |
| **Delete (Local)** | Hide items from your local view; choice persists in `localStorage`. |
| **Syntax Highlighting** | Shiki-powered build-time code highlighting in Markdown. |
| **Live Reload** | Eleventy dev server rebuilds on content changes. |

## Development

### Full Dev Stack

```bash
npm run dev
```

Starts three processes in parallel:
- **Watcher server** (`node watcher.js`) — handles file uploads on port 3001
- **Asset builder** (`node build-js.js --watch`) — watches `src/assets/js/*.ts`
- **Eleventy serve** (`eleventy --serve`) — builds the site and serves with live reload

### Static Dev Server

If you only need the site without the upload watcher:

```bash
npm run dev:static
```

### Port Conflicts

If port `3001` is already in use, the watcher will print a clear error and exit. Start on a different port:

```bash
WATCHER_PORT=3002 npm run dev
```

The frontend automatically picks up the port via `src/_data/watcher.js`, which injects the correct URL into the template's `data-watcher-url` attribute.

## Content Authoring

All content goes in `src/content/`. The file extension determines which layout is used.

### Markdown

```md
---
title: My Note
date: 2026-04-23
tags:
  - ideas
  - draft
---

Your content here.
```

### HTML

Full standalone HTML documents are supported. They render inside a Shadow DOM so their CSS is fully isolated from the app chrome.

```html
---
title: Custom Dashboard
date: 2026-04-23
tags: [portfolio]
---
<!DOCTYPE html>
<html>
<head>
  <style>/* your styles */</style>
</head>
<body>
  <h1>My Dashboard</h1>
</body>
</html>
```

### Plain Text

`.txt` files are rendered as preformatted text with a document heading.

### Front Matter

Front matter is optional. If you omit `title`, it is derived from the filename. If you omit `tags`, they are extracted automatically from the content body.

## Drag-and-Drop Ingestion

1. Start the dev stack: `npm run dev`
2. Drag one or more `.md`, `.html`, or `.txt` files onto the drop zone at the bottom of the left sidebar.
3. Files are uploaded to the watcher server, written to `src/content/`, and Eleventy rebuilds the site.
4. If a file already exists, you'll get a confirmation prompt to overwrite.

**Accepted types:** `.md`, `.html`, `.txt`  
**Accepted MIME types:** `text/markdown`, `text/html`, `text/plain`, `application/octet-stream`

## Search

The search index is generated at `/search-index.json` during the build. The sidebar fetches it on page load and initializes Fuse.js for fuzzy full-text search across titles and tags.

- Type in the search box to filter the index in real time.
- Clear the query to show all items again.

## Testing

```bash
npm test
```

Runs the full Vitest suite:
- **Property-based tests** (fast-check) for deriveTitle, HTML isolator, and index-pane completeness
- **Unit tests** for MIME type validation, conflict detection, tag extraction, and Markdown rendering
- **DOM tests** using jsdom for index-pane and html-isolator components

Run a specific test file:

```bash
npx vitest --run src/tests/html-isolator.test.ts
```

## Building for Production

```bash
npm run build
```

1. Compiles TypeScript assets with esbuild
2. Runs Eleventy to generate the static site into `_site/`

The output is a fully static bundle with no server-side runtime requirements.

## Deployment

The `_site/` folder is a completely static bundle. Upload it to any static host:

- [Netlify](https://netlify.com)
- [Vercel](https://vercel.com)
- [GitHub Pages](https://pages.github.com)
- Any CDN or file server

> The drag-and-drop ingestion feature requires the Node watcher server, so it is only available during local development.

## Troubleshooting

| Problem | Cause | Solution |
|---------|-------|----------|
| "Ingestion server unreachable" | Watcher not running, or port conflict | Check `node watcher.js` is running. If port 3001 is taken, use `WATCHER_PORT=3002 npm run dev` |
| Uploaded HTML renders the whole app inside itself | Self-referential fetch in old html-isolator | Fixed in current version. Ensure `html-page.njk` uses inline `<script type="text/html">` + `src="#id"` |
| Styles from uploaded HTML leak into the app | CSS not isolated | HTML content renders in Shadow DOM; verify `html-isolator.ts` is built and loaded |
| Sidebar empty after hydration | `renderIndex` target mismatch | Ensure `#index-content` wrapper exists in `base.njk` and `renderIndex` targets it |
| Tests fail on `deriveTitle` whitespace | Flaky property test with edge-case whitespace-only titles | Rerun; this is a known pre-existing flaky test |

## Architecture Decisions

### Why no frontend framework?
The app is intentionally lightweight: vanilla TypeScript, custom elements, and DOM APIs. This keeps bundle size near zero and avoids framework churn for a read-only knowledge base.

### Why Shadow DOM for HTML content?
Uploaded HTML often includes its own `<style>` tags, global resets, and CSS custom properties. Rendering it in an open Shadow Root provides bidirectional style isolation: the app's CSS doesn't leak in, and the content's CSS doesn't leak out.

### Why Fuse.js instead of a server index?
The site is fully static. A client-side search index means search works on any static host without a backend.

### Why a separate watcher server instead of an API route?
Eleventy's dev server is a static file server. A separate Node HTTP server handles multipart uploads, file validation, and writing to disk. This separation keeps concerns clean and works with any static host in production.

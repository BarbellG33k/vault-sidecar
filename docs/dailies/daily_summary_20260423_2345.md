## Issues Ran Into

### 1. Upload Shows "Ingestion Server Unreachable"
**Description:** Drag-and-drop file uploads always failed with the message "Ingestion server unreachable. Run `npm run dev` to start it." even though the dev stack appeared to be running.

**Root Cause:** Port `3001` was already occupied by an unrelated Node process (`reading-tracker/server`). `concurrently` silently swallowed the watcher crash, so the other processes (Eleventy, asset build) kept running while the upload endpoint was dead. The frontend lumped all HTTP failures (CORS blocks, 404s, 500s) into the generic "unreachable" error.

### 2. HTML Content Renders the Entire App Inside Itself
**Description:** After uploading full HTML documents, the stage pane displayed a broken nested view of the sidebar, a "sun" radial-gradient artifact, and meta-repeated UI elements.

**Root Cause:** `html-page.njk` rendered `<html-isolator src="{{ page.url }}">`, which caused the component to fetch its own fully-rendered page. That page contained the entire app shell (sidebar, stage, scripts) plus another `<html-isolator>`, creating infinite self-nesting. The "sun" was a radial gradient from the uploaded HTML's CSS being rendered multiple times.

### 3. Drop Zone Disappears After JS Hydration
**Description:** After moving the drop zone into the left sidebar, it vanished as soon as the client-side JS hydrated the index list.

**Root Cause:** `renderIndex` was called on `#index-pane`, which wiped the container's `innerHTML` and replaced the entire sidebar content, destroying the ingestion zone element.

### 4. deriveTitle Property Test Is Flaky
**Description:** `npm test` intermittently fails on `deriveTitle.test.js` when fast-check generates a whitespace-only title string.

**Root Cause:** Pre-existing test edge case; not related to any changes made today.

## Solutions

### 1. Upload "Ingestion Server Unreachable"
**Fix:** Three coordinated changes:
- Made watcher port configurable via `WATCHER_PORT` env var (default still 3001).
- Added explicit `EADDRINUSE` error handling in `watcher.js` with a helpful console message.
- Created `src/_data/watcher.js` to expose the watcher URL to 11ty templates, injecting it into the drop zone via `data-watcher-url`.
- Added `response.ok` check in `ingestion-zone.ts` so non-network HTTP errors (404, 500, 422) show the actual server message instead of the misleading "unreachable" text.

**Files Modified:**
- `watcher.js`
- `src/_data/watcher.js` (new)
- `src/_includes/base.njk`
- `src/assets/js/ingestion-zone.ts`

### 2. HTML Self-Referential Rendering
**Fix:** Two coordinated changes:
- `src/_includes/html-page.njk` now embeds raw uploaded HTML in a `<script type="text/html" id="raw-html-content">` tag, then points `<html-isolator src="#raw-html-content">` at it.
- `html-isolator.ts` learned to read inline content when `src` starts with `#`: it queries the DOM for that element ID and uses its `textContent` directly instead of fetching.
- `stage-pane.ts` also updated: when loading an HTML item from the sidebar, it fetches the rendered page, extracts the raw HTML from the `<script type="text/html">`, and passes it directly to `isolator.renderShadow()`.

**Files Modified:**
- `src/_includes/html-page.njk`
- `src/assets/js/html-isolator.ts`
- `src/assets/js/stage-pane.ts`

### 3. Drop Zone Vanishing on Hydration
**Fix:** Added an `#index-content` wrapper inside `#index-pane` around the dynamic list/search/tags area. Changed all `renderIndex` calls to target `#index-content` instead of `#index-pane`, so hydration only replaces the scrollable list area and leaves the drop zone intact.

**Files Modified:**
- `src/_includes/base.njk`
- `src/assets/css/main.css` (added `#index-content` styles)

### 4. deriveTitle Flaky Test
**Mitigation:** Acknowledged as pre-existing; re-running tests usually passes. No fix applied today.

## Lessons Learned

- **Port conflicts are silent killers in `concurrently` stacks.** Always check if the expected port is actually bound to the right process, not just that the command didn't crash visibly.
- **Self-referential fetching is a classic Shadow DOM / custom element trap.** If a component fetches `src` and that `src` is the same page the component lives on, you get infinite nesting. Inline data (`<script type="text/html">`) is a clean escape hatch.
- **Hydration boundaries matter.** Rendering into a container that also holds static/durable elements will destroy them. Use wrapper elements to isolate dynamic from static regions.
- **Error messages should distinguish network failures from HTTP errors.** A server that responds with 422 is "reachable but rejecting" — users need to know the difference.
